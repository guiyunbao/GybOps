# 常见卡点

返回 [新手使用手册](README.md)。

下面每一条都先给出最可能的原因和要打开的页面。按顺序看完仍无法恢复时，把页面上的错误原文、任务或文章编号记下来，再查 [部署文档](../deployment/DEPLOYMENT.md) 里的日志和进程说明。

## 登录进不去

打开 <http://localhost:18080/geo_admin/login>。本机脚本安装出的账号是 `admin`，密码是 `password`。

页面打不开时，先确认 Docker 里的 web 服务已经启动，并且浏览器端口与 `APP_PORT` 一致。默认是 `18080`。

提示账号或密码错误时，确认没有把生产环境的随机初始密码和本机默认密码记混。生产环境的初始密码在首次安装日志里，账号已存在时不会再次打印。找回方式见 [部署文档](../deployment/DEPLOYMENT.md)。

能打开登录页、提交后回到登录页时，检查访问地址是不是后台前缀。默认前缀是 `geo_admin`。改过 `ADMIN_BASE_PATH` 后，要用新前缀。

## 模型检测失败

进入 **系统 → AI配置器 → AI模型配置**，打开这个模型的检测结果。

- 密钥或权限被拒绝：到服务商控制台核对密钥是否有效、是否有该模型的调用权限。
- 地址或模型不存在：核对基础地址和模型 ID，兼容接口不要多拼一层路径。
- 请求过于频繁或额度不足：等额度恢复，或换一个有额度的模型。
- 超时：确认运行 GEOFlow 的机器能访问该服务商，再把检测重试一次。

检测通过之前，任务和工作台会一直提示模型不可用。多个管理员的模型为什么不能互相使用，见 [管理员 AI 模型隔离与共享](../admin-ai-config-sharing-runbook.md)。

## 任务一直不动

进入 **内容 → 任务管理**，先看任务是启用还是暂停，再打开 **最近 Job**。

Job 里已经有失败原因时，按原因处理：模型未就绪、标题不足、知识库没有切片，分别回到 AI模型配置、标题库和知识库详情。

Job 停在排队、Worker 状态是「已失联」或没有任何进程时，队列或定时任务没有在跑。用本机 Docker 时，确认 queue 和 scheduler 容器处于运行中。恢复进程后，回到任务页使用页面上的重试或再次启动，并刷新 Job 看新的状态。

页面已经提示「已提交」时，文章不会立刻出现。等 Job 结束后再打开 **内容管理** 的文章列表。

## 文章发不出去

打开这篇文章，依次看：

1. 必填项是否完整，包括标题、正文和分类。
2. 风险扫描是否阻断。命中敏感词时，改正文或调整 [敏感词](system.md#安全与审计) 后再扫描。
3. AI 质检是待复核、阻断、失败还是过期。过期表示正文或知识已经变了，需要重新检查。
4. 发布时间是不是还在未来。

质检结论的含义和处理见 [AI 质检运行手册](../ai-quality-inspection-runbook.md)。本站发布成功，只表示 GEOFlow 前台可以展示。外部站点还要到 [分发队列](distribution.md#分发管理) 看那一次的结果。

## 前台看不到

先确认文章状态是已发布，而不是草稿、待审核或仍在垃圾箱。

然后用浏览器直接打开 <http://localhost:18080>。首页模块依赖某个分类时，该分类下要有已发布文章，模块才会出现。

首页有、详情没有时，检查分类地址和文章地址是否保存成功。改过站点名称或主题后，刷新一次页面。

外部渠道上的页面看不到时，回到分发队列核对远端状态，本站前台的发布不会自动说明远端已经成功。

## 侧栏少了一项

菜单按账号权限显示。

- **分发管理**、**用户与权限**、**系统更新**、**URL智能采集**、**AI搜索与信源**、数据中心里的 **多站分发**，只给具备受保护工作流权限的管理员。
- 普通管理员在分发组看到的是 **内链投放**。
- 超级管理员的内链投放在分发管理的页内导航中，不单独占侧栏一项。

用有权限的账号仍看不到时，确认登录的是预期账号，并刷新页面。手工拼一个地址不能绕过权限，服务端会拒绝。

右上角 **账户与权限** 所有管理员都可以打开，用来改自己的密码，并管理已经批准的浏览器客户端。
