# AI 工作台、AI 配置与网站设置

返回 [新手使用手册](README.md)。

AI 工作台在侧栏最上方。AI配置器和网站设置在 **系统** 组。第一次闭环先完成模型检测，其余网站设置可以在文章发布后再改。

## AI 工作台

AI 工作台用对话说明后台功能的位置和操作顺序，也可以按现有配置整理一个任务草稿。它按当前账号的权限给出入口。回答不能代替你到目标页面上的确认。

侧栏点击 **AI 工作台**。页面上先看当前模型是否就绪。未就绪时，会给出原因和检测入口。

第一次建议这样做：

1. 模型已经检测通过后，直接问一个具体问题，例如「创建任务之前要准备什么」。
2. 看回答里的功能入口，点进去核对页面。
3. 需要新建任务时，点击「创建任务」，或输入「帮我创建一个文章发布任务」。按提示补齐标题库、模型和栏目。每轮只需要回答它问到的项目。
4. 摘要确认后，再点击创建。新任务会处于暂停，不会马上生成文章，也不会向外发布。

对话出现在当前会话里，入口指向你有权打开的页面。任务创建成功后，可以在任务管理里看到这条暂停的任务。要真正生成文章，回到任务里按 [任务管理](content.md#任务管理) 的步骤启动一次小批量。

模型未就绪、额度用尽或生成中断时，问题会留在页面上。先到 AI模型配置重新检测，再发送一次。工作台的会话只属于当前管理员。

任务草稿的字段范围、暂停规则和故障处理见 [AI 工作台与系统帮助](../ai-workspace-runbook.md)。

## AI配置器

AI配置器集中管理对话模型、Embedding 模型、提示词和搜索信源。文章生成、标题生成、质检和工作台问答都依赖这里的对话模型。

侧栏点击 **AI配置器**。页上的入口是：

- **AI模型配置**
- **提示词配置**
- **其他提示词**
- **AI搜索与信源**（仅具备受保护工作流权限的账号可以使用）

先看活跃模型数量。数量为 0 时，后面的任务和工作台都不会开始。

### AI模型配置

打开 **AI模型配置**，新增一个模型。名称自己能认出即可。接口地址、密钥和模型 ID 要与服务商文档一致。兼容 OpenAI 的接口通常填写基础地址，不要自行多拼一层路径。

保存后点击连接检测。检测通过后，把这个模型用于第一次任务。知识库要做真实向量时，再另加一个 Embedding 模型。

列表里该模型为可用，检测结果是成功。任务和工作台可以选择它。

检测失败时，看页面上的状态码和错误说明：密钥或权限问题、地址或模型 ID 不存在、请求过于频繁、网络超时，分别回到服务商控制台核对。多个管理员如何共用或隔离模型，见 [管理员 AI 模型隔离与共享](../admin-ai-config-sharing-runbook.md)。

停用模型前，先看还有哪些任务在用它。

### 提示词配置

**提示词配置** 管理正文生成用的提示词，决定文章的结构、语气和事实边界。**其他提示词** 管理标题、质检等专用场景。

第一次使用时，先打开列表，选用系统里已有的一条，用 1 篇文章看效果。要改写法时，复制一条再改，保留原来的版本。

任务里能选到这条提示词。新任务使用新提示词，已经生成的文章不会自动改写。

提示词改完后文章明显跑题时，把任务改回原来的提示词，再生成 1 篇对比。

### AI搜索与信源

**AI搜索与信源** 给 AI 可见性观测和需要联网检索的能力提供搜索来源。普通文章生成可以先不配置。

具备权限时，从 AI配置器进入该页，新增一个信源，填写服务商要求的地址和密钥，保存后做连接检测。

检测通过后，再去数据中心的 AI 可见性发起观测。观测失败时，回到这条信源看检测结果和额度。

## 网站设置

网站设置在侧栏 **系统** 组。页内分区是：

- **网站与品牌**
- **首页与主题**
- **表单与线索**
- **用户与权限**（仅具备受保护工作流权限的账号）
- **安全与审计**
- **系统更新**（仅具备受保护工作流权限的账号）

改完一项，就到前台或对应列表看结果，再改下一项。

### 网站与品牌

这里维护站点名称、Logo、基础展示、友情链接和文章地址相关设置。

打开 **网站与品牌**。第一次先把站点名称改成你的品牌名，保存。

前台浏览器标题和首页名称会变成新名称。Logo 上传后，刷新前台确认图片显示。友情链接在同一分区里维护，添加后到前台页脚或主题规定的位置查看。

名称没有变化时，强制刷新浏览器缓存后再看。生产环境的域名和 HTTPS 以部署文档为准。

### 首页与主题

首页与主题决定前台用哪套外观，以及首页上有哪些模块。

打开 **首页与主题**。先看当前主题，再用预览看首页和文章页。确认外观合适后保存。

预览里的版式和前台一致。模块依赖的分类还没有文章时，前台会少一块，先发布文章再回来看。

主题包导入、复刻和检查是进阶操作。预览通过、并确认没有不可用的外部资源后，再应用到正式站点。导入步骤以页面上的检查结果为准。

### 表单与线索

这一分区包含转化表单和线索管理。表单决定前台收集哪些字段，线索管理保存访客提交的内容。

打开 **表单与线索**，进入表单列表。新建一个表单，只保留姓名、联系方式和需求三项，设为启用并保存。到前台提交一次。

回到线索列表，能看到刚才的测试提交。打开详情，把状态改成已跟进，确认列表状态一起变化。

前台没有表单时，检查表单是否启用，以及当前主题页面是否展示表单。导出含有联系方式，只发给需要跟进的人。

### 用户与权限

用户与权限用于创建后台账号、分配角色，以及签发 API Token。只有具备受保护工作流权限的管理员能进入。

打开 **用户与权限**。给同事新建账号时，只开他工作需要的权限，保存后用该账号登录验证菜单。

新账号可以登录，并且只能看到被允许的菜单。API Token 在创建时显示一次完整值，之后只保留摘要。交给命令行使用时，按 [GEOFlow CLI](../GEOFLOW_CLI.md) 配置服务地址和 Token。不再使用的 Token 立刻撤销。

自己的密码在右上角 **账户与权限** 里修改。修改成功后要用新密码重新登录。

### 安全与审计

安全与审计包含安全设置、敏感词和操作日志。

打开 **安全与审计**。第一次先打开敏感词列表，确认规则符合你们的发布要求。增加一条明确的测试词后，到文章里写入该词并做风险扫描，确认能被标出，然后删掉测试内容。

扫描结果会标出这条词。操作日志记录谁在什么时间做了哪类操作。排查配置被谁改过时，按时间和账号筛选。日志不保存完整密钥和正文。

### 系统更新

系统更新用于检查版本、备份、执行升级和回滚。只有具备受保护工作流权限的管理员能进入。本机体验默认不需要做升级。

打开 **系统更新**，先看当前版本和最近一次备份。真正升级前，确认备份可以恢复，再按页面上的计划逐步执行。

本机开发环境保持当前源码即可。生产升级、签名包和回滚见 [部署文档](../deployment/DEPLOYMENT.md) 和文档中心里的升级教程。升级失败时保留该次运行记录，按页面提示继续或回滚，不要另起一套手工改数据库。
